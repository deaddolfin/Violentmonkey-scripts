# AGENTS.md — правила работы с этим репозиторием

Общий свод для любых AI-агентов (Claude Code, Codex и др.). `CLAUDE.md` ссылается сюда.

## Что это за проект

Один userscript для Violentmonkey: кнопка импорта сцены со `stashdb.org` в локальный Stash
через GraphQL. Исходное ТЗ — `tz.txt`. Описание для пользователя — `README.md`.
Текущее состояние работ — `STATUS.md`.

## Структура

```
stashdb-to-stash.user.js   единственный файл кода (~440 строк, без зависимостей)
tz.txt                     исходное ТЗ, не редактировать
STATUS.md                  где остановились, следующие шаги
README.md                  инструкция для пользователя
AGENTS.md / CLAUDE.md      правила для агентов
```

Ни `package.json`, ни сборки, ни тестов, ни git-репозитория здесь нет. Не заводите их
без явной просьбы пользователя.

## Проверка изменений

```powershell
node --check stashdb-to-stash.user.js
```

Это единственная автоматическая проверка. Всё остальное проверяется вручную в браузере:
установить скрипт в Violentmonkey → открыть stashdb.org → нажать «→ Stash».
Агент проверить это не может (stashdb.org требует авторизации), поэтому изменения UI-селекторов
всегда помечайте как непроверенные и пишите об этом пользователю.

## Соглашения по коду

- Vanilla JS, IIFE + `'use strict'`, никаких зависимостей и бандлеров.
- Разделы файла отделяются баннерами `// ----...` — сохраняйте этот стиль.
- Комментарии в коде — на русском, поясняют *почему*, а не *что*.
- DOM строится через `createElement`; `innerHTML` только для статической разметки
  (заголовок модалки) — не подставляйте в него данные из сети.
- Стили — один инжектируемый `<style>`, все классы с префиксом `vm-stash-`.
- Все сетевые запросы идут через `gql()` поверх `GM_xmlhttpRequest` — не используйте `fetch`,
  он упрётся в CORS.
- Новые настройки добавляются одной строкой в объект `SETTINGS`; UI модалки и чтение конфига
  строятся по нему автоматически. Поле с `key` в названии автоматически рендерится как `password`.
- Ошибки сопоставления сущностей глушатся через `.catch(() => null)` — сцена создаётся даже
  если студия/актёр/тег не завелись. Сохраняйте это поведение.

## Версионирование и публикация

- Любое изменение кода → поднять `@version` в шапке (semver: patch — фикс, minor — новая фича).
- Каноническая копия лежит в репозитории `deaddolfin/Violentmonkey-scripts`
  (Forgejo → зеркало на GitHub); `@downloadURL`/`@updateURL` указывают на raw-ссылку
  ветки `main` **без хэша коммита**, иначе авто-обновление сломается — не трогайте эти строки.
- Публикация = коммит и пуш в репозиторий (на GitHub уезжает зеркалом). После правки кода
  напомните об этом и отразите факт в `STATUS.md`.

## Работа с документацией

- `STATUS.md` обновляйте в конце содержательной сессии: дата, версия, что сделано,
  следующие шаги, открытые вопросы.
- Не дублируйте одно и то же в README и AGENTS: README — для пользователя (установка,
  настройка, ограничения), AGENTS — для агента (как менять код и что проверять).
- Даты пишите абсолютные (`2026-08-16`), не «вчера»/«на прошлой неделе».
