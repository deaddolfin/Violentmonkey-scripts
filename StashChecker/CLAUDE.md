## Кратко о проекте

Userscript **Stash Checker** — форк [timo95/stash-checker](https://github.com/timo95/stash-checker),
вендорнутый в корень репозитория и доработанный под `TZ.txt`: символ-индикатор на каждый Stash-endpoint,
5 состояний записи, список тегов в настройках, цветная рамка карточки сцены.

## Команды

```powershell
npm install
npm run build     # prod-сборка → dist/index.prod.user.js; 3 warning'а про размер — норма
npm run dev       # webpack-dev-server :8080 для установки в Violentmonkey
```

`npm run build` — основная и единственная автоматическая проверка (типы через `ts-loader`).
Тестов нет. Поведение в браузере агент проверить не может: нужны реальные endpoint'ы Stash
и авторизация на сайтах.

## Окружение

- Windows 11, основная оболочка — PowerShell.
- Рабочая директория: `F:\MyProject\Violentmonkey\StashChecker`.
- Git не инициализирован — истории нет, откатиться нельзя. Перед крупным рефакторингом
  (`tooltip.ts`, `check.ts`, `stashChecker.ts`) кладите копию файла в scratchpad.
- `temp/` — сохранённые HTML-страницы от пользователя для отладки селекторов.

## Ловушки

- Не поднять `version` в `package.json` = обновление не доедет до пользователя (версия идёт
  в метаблок из `package.json`).
- Правка исходников без `npm run build` бессмысленна: в gist заливается `dist/index.prod.user.js`.
- Не менять `updateURL`/`downloadURL` в `metadata.js` — raw-ссылка gist специально без хэша ревизии.
- Не возвращать фильтрацию `tags`/`files` в GraphQL-запрос (`getDataFields`) — сломает состояния
  Tag и NoFile.
- `cardSelector` есть только для части сайтов; селекторы вёрстки хрупкие — правки в них помечать
  как требующие ручной проверки.
