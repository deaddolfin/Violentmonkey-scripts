# Stash Checker (форк)

Userscript для Violentmonkey/Tampermonkey: на порносайтах помечает сцены, исполнителей, студии,
группы и галереи, которые уже есть в вашем [Stash](https://github.com/stashapp/stash) —
символом-индикатором рядом с названием и цветной рамкой вокруг карточки сцены.

Форк апстрима [timo95/stash-checker](https://github.com/timo95/stash-checker) (базовая версия 1.2.4),
доработанный под требования `TZ.txt`. Текущая версия — **1.3.0**.

- Установка/обновление: <https://gist.github.com/deaddolfin/f1fc6ef93da98e2900be60749a1fbda1>
- План доработки: [PLAN.md](PLAN.md) · Состояние работ: [STATUS.md](STATUS.md)

## Отличия от апстрима

1. **Отдельный символ на каждый Stash-endpoint** — если подключено несколько инстансов Stash,
   рядом с элементом появляется группа символов, по одному на инстанс, со своим tooltip.
2. **Два новых состояния** — «нет файла» и «запись содержит тег из списка настроек».
3. **Список тегов в настройках** (через запятую) — задаёт, какие теги подсвечивать.
4. **Цветная рамка карточки сцены** — агрегирует состояния всех endpoint'ов для этой сцены.

## Состояния и цвета

Приоритет сверху вниз — первое подходящее состояние и определяет символ:

| Состояние | Условие | Символ по умолчанию | Цвет символа | Рамка карточки |
| --- | --- | --- | --- | --- |
| Дубликат | несколько записей на одном endpoint | `!` | orange | `yellow` |
| Содержит тег | у записи есть тег из списка настроек | `⚑` | `#d800ff` | `#d800ff` |
| Нет файла | **только сцены**: у записи нет файлов | `∅` | red | `red` |
| Есть в базе | иначе | `✓` | green (или из custom-правила) | `lightgreen` |
| Нет в базе | записей не найдено | `✗` | red | без рамки |

Теги сравниваются по имени, точно и без учёта регистра.

## Установка

1. Установите Violentmonkey (или Tampermonkey).
2. Откройте
   [raw-ссылку из gist](https://gist.github.com/deaddolfin/f1fc6ef93da98e2900be60749a1fbda1/raw/index.prod.user.js) —
   расширение предложит установку. Обновления подтягиваются оттуда же (`@updateURL`).
3. Либо соберите локально (см. «Разработка») и установите `dist/index.prod.user.js` из файла.

## Настройка

Меню расширения на любом поддерживаемом сайте → **Settings** (горячая клавиша `s`).
Там же — «Deactivate for `<сайт>`», чтобы отключить скрипт на текущем домене.

- **Stash Endpoints** — список ваших инстансов Stash: имя, GraphQL URL (базовый URL + `/graphql`),
  API key (из Settings → Security; можно оставить пустым). По умолчанию — `http://localhost:9999/graphql`.
  Рядом с именем показывается версия Stash или причина, почему подключиться не вышло.
- **Symbol** — показывать ли check / cross / tag / no-file маркеры и какими символами их рисовать.
- **Tags** — `Tag list (comma separated)`: список тегов для состояния «содержит тег».
- **Tooltip** — показывать ли теги и файлы во всплывающей подсказке, тема, формат даты.
- **Query** — метод запроса (GET/POST) и размер батча.

Теги и файлы **запрашиваются из Stash всегда** (они нужны для вычисления состояний);
опции `Show tags`/`Show files` управляют только содержимым tooltip.

## Поддерживаемые сайты

Список `@match` задан в [`metadata.js`](metadata.js) — около 60 доменов, включая stash-box'ы
(stashdb.org, fansdb, javstash, pmvstash), javdb, iwara, data18, indexxx, iafd, freeones, pornhub,
onlyfans, а также семейства сайтов MetArt, Vixen и WowGirls.

Сайто-специфичные селекторы живут в `src/stashChecker.ts`. **Рамка карточки сцены** настроена
не для всех сайтов — сейчас для `iwara.tv` (`.videoTeaser`), `javdb.com` (`.item`) и стеш-боксов
(`.SceneCard, .SearchPage-scene` в списках и поиске, `.scene-info` на странице сцены).
Для остальных сайтов селектор карточки нужно добавлять вручную.

## Разработка

```powershell
npm install       # зависимости (все в devDependencies)
npm run build     # prod-сборка → dist/index.prod.user.js (+ .meta.js); 3 warning'а про размер бандла — норма
npm run dev       # webpack-dev-server :8080, скрипт с именем «… Dev» и hot reload
```

Сборка — webpack 5 + ts-loader + SCSS; блок `==UserScript==` генерируется плагином
`webpack-userscript` из `metadata.js`. Тестов нет, проверка типов идёт при сборке.
Подробности для разработки и для AI-агентов — в [AGENTS.md](AGENTS.md).
